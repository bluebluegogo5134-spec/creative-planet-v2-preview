# 《创作星球》开发交付与 QA 闸门

## 1. 工作状态

`Backlog → Ready → Developing → Self QA → User Acceptance → Done`

只有满足进入条件的任务才能从 Backlog 进入 Ready。

## 2. Definition of Ready

每个任务开始开发前必须具备：

- 任务解决的问题；
- 本次包含内容；
- 本次明确不包含内容；
- 对应页面和参考稿；
- 正常、空、运行、暂停、成功和错误状态；
- 产品验收步骤；
- 视觉验收标准；
- 数据验收标准；
- 需要回归的旧功能；
- 目标设备和页面宽度。

缺少其中任何关键项，任务不得进入 Developing。

## 3. Definition of Done

一个任务只有同时满足以下条件才能标记 Done：

- 验收标准逐项通过；
- 没有新增控制台错误；
- 刷新和重新打开后数据正确；
- 相关单元测试和流程测试通过；
- 目标宽度无横向溢出；
- 与视觉金标准对照无未经确认的变化；
- 旧核心流程回归通过；
- 已提交预览链接、改动清单、截图、测试结果和已知问题；
- 用户需要确认的事项已经明确确认。

## 4. 固定测试数据

每次发布至少覆盖：

1. 新用户：没有项目和记录；
2. 已有三个项目，本周无创作；
3. 计时器正在运行；
4. 计时器暂停后刷新；
5. 应用在后台或锁屏 40 分钟后重新打开；
6. 本周刚好达到 4 个节点和 14 小时；
7. 周日跨到周一；
8. 首次联网后离线打开；
9. 从旧数据版本升级；
10. 导出后清空测试环境并重新导入。

## 5. 每轮交付证据包

- 当前可访问的预览链接；
- 本轮改动范围；
- 未改动范围；
- 390×844 基准截图；
- 375/390/393/402 适配结果；
- 自动测试与生产构建结果；
- 核心流程测试结果；
- PWA/离线测试结果；
- 已知问题；
- 回滚点。

## 6. 发布闸门

任何版本不得因为“页面看起来差不多”直接覆盖稳定版本。发布前必须：

1. 通过自动检查；
2. 通过核心闭环测试；
3. 通过视觉回归；
4. 通过 iPhone 真机测试；
5. 完成用户验收；
6. 建立可恢复的发布版本。
