# 《创作星球》阶段 0：现状审计与重建建议

审计日期：2026-08-30  
审计对象：`bluebluegogo5134-spec/creative-planet` 当前 `main` 分支及 GitHub Pages 线上版本

## 1. 审计结论

当前版本适合作为产品原型和视觉参考保存，不适合继续通过零散补丁扩展为稳定版本。

建议：

1. 保留当前 `main` 版本作为 V1 原型基线；
2. 建立独立的 V2 开发分支；
3. 复用已经确认的产品定位、文字、默认项目、默认周计划和可用视觉素材；
4. 重新建立数据模型、计时器状态机、组件结构、PWA 注册、测试与发布流程；
5. 在核心创作闭环通过验收前，不继续大规模调整首页视觉。

## 2. 已确认的事实

### 2.1 工程结构

- 当前是无构建步骤的静态 HTML/CSS/JavaScript PWA 原型；
- 主要运行文件为 `index.html`、`app.js`、多份 CSS、`manifest.webmanifest` 和 `sw.js`；
- 没有依赖管理、类型检查、单元测试、端到端测试或自动质量检查；
- 所有项目、计划、记录、复盘和计时状态共用一个 localStorage 对象；
- 数据没有版本迁移、导出、导入和恢复机制。

### 2.2 返工集中度

- 仓库当前共有 49 次提交；
- 其中 35 次提交标题集中在首页、Hero、插画素材、iPhone 高度和缓存修补；
- 这说明视觉修补已经占据大部分迭代，但核心数据和功能架构没有同步推进。

### 2.3 当前线上视觉问题

- `assets/home-hero-1200x760.jpg` 文件本身已经发生灰块、色带和画面缺失；
- 线上首页展示的异常不是单纯 CSS 裁切问题，继续调高度无法修复损坏的源文件；
- `home-hero.jpg` 也存在相同的素材损坏；
- 当前 CSS 通过多层覆盖和 `!important` 修复尺寸，后续调整容易再次破坏其他宽度；
- `theme.css` 中的视觉令牌又被 `styles.css` 二次定义覆盖，令牌并非真正的唯一来源；
- 首页统计在 HTML 中只有三项，第四项“14h”由 CSS 伪元素生成，展示结构与数据结构不一致。

### 2.4 当前核心功能缺口

- 计时器只有“开始”和“结束”，没有已经确认的“暂停/恢复”；
- 计时过程中仍可修改项目和创作类型，显示状态可能与实际记录归属不一致；
- 没有创作记录列表，不能查看、编辑或删除已有记录；
- 首页没有“最近记录”模块；
- 项目只能新增和切换，不能编辑阶段、下一步或归档；
- 周计划只有一份，会被直接覆盖，没有按自然周保存历史；
- 周复盘只有一份，会被下一周复盘覆盖；
- 记录没有稳定 ID，不利于后续编辑、去重和数据迁移；
- 没有数据导出/导入，浏览器数据是唯一副本。

### 2.5 PWA 与离线问题

- 仓库存在 `sw.js`，但页面和脚本没有注册 Service Worker；
- 因此当前版本不能据此认定已经具备可靠离线能力；
- `sw.js` 缓存的是 `hero.css?v=2`，页面实际加载的是 `hero.css?v=5`；
- 当前首页主图没有进入离线缓存列表；
- 需要重新验证安装、首次联网后离线启动、版本更新和旧缓存清理。

### 2.6 统计逻辑待确认

- 当前“创作节点”只统计周计划中标记为节点的日期，并且同一天最多计一个；
- 未安排为节点的日期，即使实际完成创作，也不会增加节点数；
- 周计划卡片的“已完成”却只要当天存在任意记录就会点亮，包括健身记录；
- 因此“计划完成”“实际创作节点”“创作时长”目前不是同一套口径。

## 3. 可复用资产

- 产品定位：创作陪伴，而不是严格考勤；
- 五个底部入口：首页、项目、记录、计划、复盘；
- 默认项目与默认周计划；
- 每周 4 个创作节点且累计 14 小时的目标；
- 当前已确认的文案、视觉气质和页面内容层级；
- `hero1.jpg` 至 `hero5.jpg` 中未损坏的图片；
- 以时间戳恢复运行中计时器的基本思路；
- 已有项目、周统计、补录和复盘的业务原型代码，可作为规则参考，不直接搬运为最终结构。

## 4. V2 建议范围

### P0：必须先稳定

1. 项目创建、编辑、切换和归档；
2. 开始、暂停、恢复、结束和补录；
3. 结束后生成可查看、编辑的创作记录；
4. 首页根据真实记录计算周节点和时长；
5. 当前周计划；
6. 当前周复盘；
7. 本地可靠存储、数据版本迁移、JSON 导入导出；
8. 可安装、可离线启动、可安全更新的 PWA；
9. iPhone 375/390/393/402 宽度适配和 safe-area。

### P1：P0 通过后再做

1. 历史周计划和历史周复盘；
2. 更完整的项目进度与累计投入；
3. 记录筛选和项目统计；
4. 空状态、首次使用引导和数据恢复提示；
5. 更细致的动画和视觉润色。

### 本轮明确不做

- 账号系统；
- 云端同步；
- 多人协作；
- AI 自动总结；
- 通知与复杂提醒；
- 为了视觉效果新增与核心创作流程无关的功能。

## 5. V2 放行条件

只有以下条件全部满足，V2 才能替代当前公开版本：

- 核心闭环“选择项目 → 开始 → 暂停 → 恢复 → 结束 → 保存记录 → 首页更新”通过；
- 刷新、锁屏、后台停留和重新打开后计时状态正确；
- 自动测试、生产构建和页面控制台无项目自身错误；
- 375/390/393/402 四个目标宽度无横向溢出；
- iPhone Safari 与添加到主屏幕模式通过；
- 首次联网后可以离线打开；
- PWA 更新不会清空用户数据；
- JSON 导出和重新导入可以恢复项目、计划、记录与复盘；
- 用户已确认产品逻辑和视觉金标准。
